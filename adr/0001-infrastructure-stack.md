# ADR-0001: Инфраструктурный стек — Vercel + Supabase

Статус: Accepted
Дата: 2026-08-04
Источник: [[Architecture-Overview]], раздел 3

## Контекст

Платформе требуется инфраструктура, покрывающая: row-level мультитенантную изоляцию (NFR-1, NFR-2), durable execution для Recovery (NFR-6), горизонтальный масштаб на горизонте 5 лет (NFR-11), и приемлемую скорость старта для референсного сценария (Business Goals, веха года 1). В окружении разработки уже подключены Vercel и Supabase MCP-инструменты.

## Рассмотренные варианты

1. **Vercel + Supabase** — Next.js/Vercel для приложения и функций, Supabase (managed Postgres) для БД/Auth/RLS.
2. **Классический стек** (например, AWS/self-hosted: ECS/K8s + RDS + SQS/Temporal) — больше низкоуровневого контроля, выше инфраструктурные издержки старта.

Полное сравнение по критериям — см. Architecture Overview, раздел 3.

## Решение

Выбран вариант 1 — **Vercel + Supabase**.

## Обоснование

- Supabase даёт нативный Postgres RLS — прямое покрытие NFR-1 без дополнительной обвязки.
- Vercel предоставляет готовый durable workflow движок (см. ADR-0002), закрывающий наиболее рискованную часть первой итерации (Recovery).
- Меньше инфраструктурного кода до первого рабочего референсного сценария — соответствует принципу «референсный сценарий сначала» (Vision, раздел 3).
- Уже подключено в окружении — не требует дополнительной настройки перед стартом реализации.

## Последствия

**Плюсы:** быстрый старт, готовое покрытие ключевых NFR, меньше собственного инфраструктурного кода для поддержки.

**Минусы / риски:** vendor lock-in на Vercel/Supabase-специфичные примитивы (Workflow DevKit, Supabase RLS/Auth). Принято сознательно — см. риск в Risk Register.

**Влияние на архитектуру:** Database, Workflow Engine и Deployment проектируются с учётом примитивов Vercel/Supabase. Agent Framework и Workflow-контракт (интерфейсы) должны оставаться логически независимыми от инфраструктурной реализации, чтобы миграция (если потребуется на горизонте 5 лет) не требовала пересмотра контракта агента — см. NFR-10.

## Связанные записи

- Risk Register: vendor lock-in на Vercel/Supabase (добавить при создании документа).
- Связан с ADR-0002 (durable execution зависит от этого решения).
- **Критический риск (добавлено 2026-08-04, см. [[Security]] раздел 7):** законодательство РБ/РФ требует локализации персональных данных на серверах в РБ/РФ. Vercel/Supabase по умолчанию не размещаются в РБ/РФ — потенциальный конфликт с этим ADR при обработке персональных данных. Требует решения (гибридное хранилище для PII, либо пересмотр стека) до Deployment и до подключения клиентов с персональными данными из РБ/РФ. Статус ADR остаётся Accepted для референсного сценария (внутреннее использование, без PII конечных клиентов); полная переоценка — перед реальным запуском.
