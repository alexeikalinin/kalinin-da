# ADR-0003: LLM-провайдеры — Anthropic на первой итерации с абстракцией над провайдером

Статус: Accepted
Дата: 2026-08-04
Источник: [[Architecture-Overview]], раздел 5

## Контекст

Директива прямо запрещает использование одной самой дорогой модели для всех задач (Cost Optimization). FR-15 и NFR-13 требуют выбора конкретной LLM под Execution Tier и сложность Task. При этом Product Specification/Business Goals ещё не определили окончательную юнит-экономику White Label (открытый вопрос), а Agent Framework ещё не спроектирован.

## Рассмотренные варианты

1. **Только Anthropic (Claude)** — единый провайдер, выбор модели по линейке (например, младшая/средняя/старшая) под Execution Tier/сложность.
2. **Мульти-провайдер с первой итерации** — несколько LLM-провайдеров одновременно.

Полное сравнение по критериям — см. Architecture Overview, раздел 5.

## Решение

Выбран вариант 1 с архитектурным ограничением: **Anthropic — единственный провайдер на первой итерации, но Agent Framework и Cost Optimization Router проектируются с абстракцией над понятием «модель», не хардкодящей вызовы, специфичные для одного провайдера.**

## Обоснование

- Принцип «не использовать одну модель для всех задач» реализуем и в рамках одного провайдера — линейка моделей уже даёт выбор по цене/качеству/скорости.
- Мульти-провайдерная поддержка добавляет сложность в Agent Framework и Prompt Architecture до того, как подтверждена экономическая необходимость (юнит-экономика White Label ещё не решена — Business Goals, Open Question).
- Абстракция над провайдером в контракте агента превращает будущее расширение до мульти-провайдера в добавление реализации за существующим интерфейсом (Cost Optimization Router), а не в пересмотр Agent Framework — соответствует принципу расширяемости без переписывания архитектуры (Vision).

## Последствия

**Плюсы:** простота первой итерации Prompt Architecture и Agent Framework, соответствие принципу выбора модели по задаче без лишней сложности.

**Минусы / риски:** зависимость от одного провайдера моделей в первой итерации — принято сознательно, компенсируется архитектурной абстракцией, а не запретом на будущее расширение.

**Влияние на архитектуру:** Cost Optimization (документ) описывает Router как интерфейс, независимый от конкретного провайдера; Prompt Architecture не встраивает провайдер-специфичные допущения в контракт роли.

## Связанные записи

- Открытый вопрос экономики White Label (Business Goals) может инициировать пересмотр в сторону мульти-провайдера — пересмотр не потребует нового ADR к контракту Agent Framework, если абстракция соблюдена.
