# ADR-0002: Durable execution — Vercel Workflow DevKit

Статус: Accepted
Дата: 2026-08-04
Источник: [[Architecture-Overview]], раздел 4
Зависит от: ADR-0001 (инфраструктурный стек)

## Контекст

NFR-6 требует, чтобы состояние Workflow переживало сбой платформы без потери выполненной работы, а Recovery (Vision, Glossary) должен продолжать исполнение Project автоматически, без вмешательства человека. Это один из наиболее рискованных участков первой итерации — директива прямо предостерегает от недооценки такого рода механик (см. риск #5 первичного анализа директивы).

## Рассмотренные варианты

1. **Готовый durable workflow движок** — Vercel Workflow DevKit (в рамках стека ADR-0001).
2. **Собственный механизм** на базе Queue + БД с ручным чекпоинтингом состояния.

Полное сравнение по критериям — см. Architecture Overview, раздел 4.

## Решение

Выбран вариант 1 — **Vercel Workflow DevKit**.

## Обоснование

- Durable execution «из коробки»: шаги и состояние Workflow переживают рестарт по дизайну продукта — не требует написания и тестирования собственной чекпоинт-логики.
- Поддерживает декларативную конфигурацию шагов/ретраев — прямо покрывает NFR-4 (расширяемый Execution Tier как конфигурация, а не код) и NFR-5 (параллельные шаги для Fast-уровня).
- Снижает риск ошибок именно в Recovery-логике — по своей природе трудно тестируемой и критичной для доверия к автономности системы (Vision, «минимальное вмешательство человека»).
- Соответствует масштабу команды (одно агентство, не крупный инженерный отдел) — меньше собственного кода для долгосрочной поддержки, что напрямую поддерживает цель «развиваться годами без переписывания архитектуры».

## Последствия

**Плюсы:** низкий риск в самой критичной для автономности подсистеме, декларативная поддержка Execution Tier и параллелизма без дополнительного кода.

**Минусы / риски:** зависимость от конкретного продукта Vercel для ядра Workflow Engine — усиливает vendor lock-in, зафиксированный в ADR-0001.

**Влияние на архитектуру:** Workflow Engine (документ) описывает модель Workflow в терминах, совместимых с шаговой моделью Workflow DevKit; Agent Framework определяет контракт Agent независимо от того, как именно Workflow Engine его вызывает — это сохраняет возможность замены движка в будущем без пересмотра контракта агента.

## Связанные записи

- Зависит от ADR-0001.
- Risk Register: зависимость Recovery-механики от специфичного продукта (Vercel Workflow DevKit).
