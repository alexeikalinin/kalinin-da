## Часть 2: Что обязательно перед стартом кода (Этап 2)

Не просто "документация написана" — по директиве нужен явный шаг перед переходом к коду:

1. **Независимое техническое ревью пакета документации** (RISK-07, Testing раздел 4) — рекомендовано, но не выполнено на момент завершения Этапа 1. Предлагаю это как первый шаг перед Этапом 2, а не пропускать.
2. **Риск локализации персональных данных.** Основной поток (лиды с лендингов) уже закрыт архитектурно — RISK-03a (отдельная система хранения в РБ, вне стека платформы). Остаточный риск RISK-03b (Research Agent может случайно сохранить данные третьих лиц с существующего сайта клиента) — открыт, низкий приоритет, не блокирует старт кода. Полная переоценка обоих — перед Deployment → Production (White Label) (см. Deployment, раздел 2).
3. Ваше финальное утверждение — "можно начинать писать код" — отдельное явное действие, не автоматическое следствие завершения последнего документа.

## Часть 3: Roadmap реализации (Этап 2), по вехам Business Goals

| Веха | Цель | Что нужно от документации |
|---|---|---|
| **Год 1** | Референсный сценарий работает end-to-end (Owner, референсный конвейер ролей, включая Recovery и Reflection) | Весь пакет документации — прямая основа реализации; RISK-05 (калибровочный долг) закрывается по итогам этой вехи |
| **Год 2** | Мультитенантность подтверждена в проде — минимум один White-label пользователь работает параллельно с Owner | Требует переоценки RISK-03b перед открытием Production (White Label) (Deployment, раздел 2); актуализации Backlog п.1-2 (роли внутри Agency, биллинг) |
| **Год 3–5** | Расширение библиотеки ролей и горизонтальное масштабирование без изменений в контракте Agent Framework | Backlog п.3 (новые роли через Agent Architect); Scaling (документ) как руководство к действию |

## Часть 4: Как поддерживать документацию после старта кода

Согласно принципу директивы ("документация — Single Source of Truth", Glossary): любое архитектурное изменение в ходе реализации сначала отражается в соответствующем документе `docs/03-architecture/` (через RFC при значимом пересмотре, см. RFC Index), и только потом — в коде. Roadmap не описывает это как отдельный процесс — это уже сквозной принцип, действующий с Этапа 1 и продолжающийся на Этапе 2.
