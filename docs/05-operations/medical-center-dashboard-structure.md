# Дашборд для медицинских центров — эталонная структура

Статус: v1.0 — черновой стандарт вертикали, основан на разборе готового отраслевого шаблона DataLens "MedAnalytics 360" (галерея `dwkw8fi7fzsoy`, 2026-08-20) + реальном опыте Медавеню.

Назначение: показать, из чего должен состоять полноценный дашборд для мед. центра, чтобы владелец/маркетолог клиники реально видел, как идут дела — не только расход на рекламу. Дополняет [[Client-Dashboard-Playbook]], не заменяет его: тот описывает КАК подключать `ad_stat`, этот — ЧТО ещё нужно подключить сверху для вертикали "медицина".

## 0. Что показал разбор эталонного шаблона

"MedAnalytics 360" — не абстрактный дизайн, а копия реального продакшн-стека клиники: **Bitrix24 CRM + МИС "Инфоклиника"**, данные агрегируются в ClickHouse. Видно по служебным полям датасетов (`UF_CRM_ADVID_INFOCLINICA`, `UF_CRM_DCODE_INFOCLINICA`, `UF_CRM_TREATCODE_INFOCLINICA` и т.д. — префикс `UF_CRM_` — это "пользовательские поля" Bitrix24).

8 датасетов шаблона — по сути карта нужных источников:

| Датасет | Что внутри | У нас есть? |
|---|---|---|
| Директ (демо) | Расход/клики/показы/CTR по дням, кампания = названа по услуге (`заказ_узи_живот_006`) | ✅ `ad_stat` (без семантики "кампания = услуга") |
| Метрика (демо) | Визиты по дням, **источник трафика** (Google/Яндекс/соцсети/переходы из рекомендательных систем), поисковая система, привязка к кампании/группе Директа | ⚠️ частично — у нас только конверсии по целям, не полная разбивка визитов по источникам |
| Записи на прием (демо) | Заявка/запись: пациент, врач, дата, тип клиента (новый/вернувшийся), рекламный источник записи (`UF_CRM_ADVID`), филиал, код услуги | ❌ нет — это МИС/CRM клиники |
| Приемы — доктора и пациенты (демо) | Визит: врач, пациент, услуга, первичность | ❌ нет |
| Приемы — финансы (демо) | Визит: выручка построчно, **источник** (маркетинговый канал), доктор, услуга, когортный анализ возвращаемости | ❌ нет — это самое ценное поле: выручка привязана к каналу привлечения |
| Возвращаемость в центр (демо) | Когортный анализ повторных визитов | ❌ нет |
| Операционный (демо) | Загрузка врачей/кабинетов | ❌ нет |
| О дашборде (демо) | Тех. справка, не данные | — |

Вывод: у полного клона ключевая метрика — не CTR/CPA, а **выручка и повторные визиты в разрезе рекламного источника** (поле "Источник" на уровне финансовой строки приёма). Это ROI-аналитика, а не только медиастатистика — и её физически нельзя построить без данных МИС/CRM клиники.

## 1. Три уровня зрелости дашборда для мед. центра

Не пытаться сделать всё сразу — предлагать клиенту как путь роста.

### Уровень 1 — Медиа-обзор (есть сейчас, на `ad_stat`)
Что уже умеем: расход, клики, показы, CTR, конверсии по целям (звонок, заявка, онлайн-запись), CPA/CR — раздельно по Google Ads/Яндекс.Директ из-за валюты. Это уровень "сколько потратили и сколько получили лидов по данным рекламных кабинетов".
Ограничение: конверсия — это клик по номеру/отправка формы, а не факт визита или оплаты. Двойной счёт и сломанные цели (см. [[Медавеню-client-setup]]) искажают именно этот уровень, если его не перепроверять.

### Уровень 2 — Полный трафик сайта (Метрика, без доп. интеграций)
Добавляет: разбивку визитов по ВСЕМ источникам (не только платным) — органика, соцсети, переходы из справочников (2Гис, Я.Карты, ПроДокторов), прямые заходы. Показывает долю платного трафика в общем потоке и помогает понять, не переплачивает ли клиника за то, что и так пришло бы органически.
Требует: у нас уже есть доступ к Яндекс.Метрике клиента (`YANDEX_AGENCY_ACCESS_TOKEN`, см. [[Медавеню-client-setup]]) — не хватает только синка визитов-по-источникам (сейчас синкаются только конверсии по целям, не сырые визиты/источники). Инкремент к текущему пайплайну, не новая интеграция.

### Уровень 3 — Путь пациента (нужна интеграция с МИС/CRM клиники)
Добавляет: реальную выручку и повторные визиты в разрезе канала привлечения — то есть настоящий ROAS/ROMI по каналу, а не прокси через "конверсии". Это ядро того, что показал шаблон.
Требует данные, которых у агентства по умолчанию нет:

1. **CRM/МИС клиники** — Bitrix24, amoCRM + МИС (Инфоклиника, MedElement, MedWork, 1С:Медицина, qMS, YClients) — записи, пациенты, врачи, услуги, оплаты. Обычно доступ через API/вебхуки CRM, не через МИС напрямую.
2. **Коллтрекинг** (Calltouch, Callibri, UIS, Mango Office, Ringostat) — для мед. центров звонок остаётся основным каналом записи, и без коллтрекинга атрибуция звонка на конкретное объявление/кампанию невозможна — только "конверсия = клик по номеру", без факта разговора и его результата.
3. **Связующий идентификатор** между рекламным кликом и записью в CRM — обычно `yclid`/`gclid`/UTM-метки, сохранённые в CRM-сделке как кастомное поле (в шаблоне — `UF_CRM_ADVID_INFOCLINICA`). Без этого поля в CRM объединить `ad_stat` с выручкой невозможно даже имея доступ к CRM.
4. Опционально — **репутация**: рейтinges/отзывы (Яндекс Карты, 2Гис, ПроДокторов, Zoon) — в медицине сильно влияют на конверсию из показа в запись, но плохо ложатся в тот же дашборд (другая частота обновления), обычно отдельный виджет-сводка.

## 2. Рекомендуемая структура полного дашборда (когда доступен Уровень 3)

По образцу шаблона, адаптировано под то, что реально нужно владельцу клиники:

1. **Пульс клиники** — верхнеуровневые KPI за период: выручка, кол-во пациентов (всего/новых), средний чек, доля повторных визитов, тренд по неделям.
2. **Маркетинг → Заявки** — воронка от показов до записи: показы → клики → заявки/звонки → подтверждённые записи → визит → оплата, с CPA на каждом шаге, раздельно по платформе/валюте.
3. **Источник → Выручка** — таблица/дерево: канал (Google Ads/Яндекс.Директ/органика/соцсети/повторные) → выручка → ROMI = (выручка − расход) / расход. Это то, ради чего строится Уровень 3.
4. **По направлениям/услугам** — какая услуга/направление приносит больше всего записей и выручки на вложенный рубль/доллар рекламы — помогает перераспределять бюджет между направлениями, а не только между платформами.
5. **По врачам** (опционально, чувствительно) — загрузка и выручка по врачу; показывать клиенту только если он сам просит — конфликтный срез внутри клиники.
6. **Возвращаемость** — когортный анализ: доля пациентов, вернувшихся через 1/3/6/12 месяцев — маркетинговая ценность удержания vs привлечения.
7. **Качество трафика** (Уровень 2) — доля платного/органического/справочного трафика, чтобы видеть общую картину, не только рекламную часть.

## 3. Как это позиционировать

Специализация на медицинской рекламе — сильная сторона именно потому, что этот вертикальный разрыв (реклама ⇄ реальная выручка через МИС) закрывают немногие агентства: большинство останавливается на Уровне 1 (кабинетные метрики). Наш текущий стек (`ad_stat`, датасет в DataLens, весь плейбук [[Client-Dashboard-Playbook]]) уже закрывает Уровень 1 быстро и без ошибок валют/дублей — это готовая база для апсейла на Уровень 2 (почти бесплатно, только доп. синк) и Уровень 3 (отдельный проект интеграции с CRM клиники, самый ценный для клиента и самый защищённый от копирования конкурентами).
